# F-14 Fleet Defender — retail-matching reconstruction notes

Goal: source in `src/*.C`/`*.ASM` that compiles to function bodies
instruction-equivalent to the retail oracle
`/home/xor/games/f14gold/Fleetgold/F14GOLD/F14.EXE`.
"Equivalent" = same instructions, operands, and control flow, modulo
relocations, DSEG addresses, and the pinned artifacts listed below —
byte-identical is not required where the difference is a relocation
value or an assembler encoding choice.

## Toolchain

- **Compiler**: Microsoft C 6.00 (`c6/BIN/CL.EXE`), run under kvikdos.
  Flags (small model, per `src/MAKEFILE`):
  `/FPa /G2 /Gs /AM /Osegcl /nologo /c /Zi /Zd -IF:\`
  Per-module overrides in `build_all.sh` `MODULE_FLAGS` — retail mixed
  optimization flags; currently only `ddd` differs (`/Oaegcls`).
- **Assembler**: `/usr/bin/uasm -Zm` (MASM-compat mode; `OPTION SCOPED`
  for proc-local labels). MASM 5.10 (`$F19/dos/masm510`) for old-syntax
  modules; `_rp` is UASM-only (MASM 6 `word` data types).
- **Linker**: LINK 5.31.009 (`C700/BIN/LINK.EXE`) under kvikdos via
  `src/F14.LRF`. `src/MPSLIBM.LIB` is a *generated stub* (45
  `xor ax,ax; call` bodies) — the real MPS raster lib exists only in gold.
- **Build**: `bash build_all.sh {c|asm|link|all}` — takes *modes*, not
  module names. Per-module rebuild + relink + map regen:
  `bash tools/relink_check.sh <basename>...` (not executable; run via bash).
  Full link prints ~80 pre-existing `L2025` duplicate-symbol errors from
  MLIBCA/CRT (`__amblksiz`, `__ctype_`) — noise; check `build/obj/F14.EXE`
  timestamp, not the error count.

## Maps and anchoring

- `build/f14_named.map` — regenerated by `relink_check.sh` /
  `tools/linkmap2mzmap.py` from `build/obj/F14.MAP` after every link.
  **Verify the map is newer than the EXE** — a stale map produced a
  whole sweep of false 0/506 DIFFs.
- `analysis/gold/gold.map` — gold CODE_n segment paras (Ghidra extents).
- `analysis/gold/gold_named.map` — gold function anchors.
- `analysis/gold/aligned_anchors.tsv`, `classified.tsv`,
  `gold_to_source.tsv`, `callpairs.tsv` — pairing tables; some are stale
  after relinks — prefer `verify_current.txt` output.

**Re-anchor before believing a DIFF.** Named-map offsets are
consistently ~5-6 bytes late on some functions (`_Sound`, `_GetRadarGTNum`,
`_GetPlaneLanding`, `_HsdCrt`): the map address lands mid-function.
Check: disassemble a few bytes *before* the mapped offset; a real
prologue (`enter`, `push bp/mov bp,sp`) usually sits right there.
`_Sound` was "radically different" only because the anchor started at a
preceding `retf`; the true body is exact.

## Verification loop

1. Get both addresses (gold map + cand map).
2. Extract load images (skip MZ header; paras*16):
   `d[hdr*16:(pg-1)*512+(lp or 512)]`.
3. `ndisasm -b16 -o<linear>` both extents side by side
   (`tools/fdiff.py NAME`, `tools/triage_fn.py NAME`, or the
   `pairdiff.py` pattern: interleave `G:`/`C:` lines, mark `!!`).
4. Normalize before comparing: far-call targets, branch target
   addresses, DSEG offsets, function-pointer constants, imm widths.
5. `tools/realdiff.py` does this normalization automatically over a
   verify log; `tools/semdiff.py` classifies MATCH/LAYOUT/ARTIFACT/REAL.
6. Full sweep: `tools/verify_build.py GOLD.EXE gold.map MY.EXE
   my_named.map classified.tsv matches.txt -j N`.

## Diff classification (the important part)

A reported DIFF is usually **not** a source bug. Triage order:

- **Stale anchor** — disasm shows no prologue / mid-code start. Fix by
  re-anchoring, not by editing source. (~10% of the list)
- **Dead code** — function exists in our source but not in gold at all
  (`_UpdatePalBuf`'s `M0` packet check has zero `'M'` compares in gold;
  MAP.C's `X2map`/`Y2map`/`mplot`/`MapLoc`/`Project2D`/`DeProject2D`
  were dead-stripped). No action.
- **Library/runtime** — `_MPSLIBM_TEXT`×7 (real port-IO driver bodies;
  our stubs are placeholders), CRT (`__amsg_exit`, `_vsprintf`,
  `__setargv`). Needs real reimplementation, not source tweaks.
- **Data layout** — same instruction, different DSEG operand. Check
  `analysis/gold/dseg_pairs*`: gold `0x669a`↔ours `0x619a` etc. Same
  variable, shifted offset. Also covers table bases (`aiactions`,
  `GroundObjectScale`), far-pointer constants (`AAFIRE` BSS stub),
  embedded-string offsets, and far-call function pointers.
- **Pinned regalloc** — variable in register vs stack slot, si↔di swap,
  dual-vs-shared epilogue, spill-vs-recompute. MSC6 heuristic, not
  reachable from source shape (multiple variants tried).
- **Operand-order canonicalization** — `cmp [x],ax` vs `cmp ax,[x]`,
  `a+b` vs `b+a`, or-chain order. MSC6's `e` pass orders leaves by an
  internal weight independent of source order (3+ source forms tried on
  `_Sound`, `_MsgBox`, `_NHorz`; all fold identically).
- **Store-group scheduling** — MSC6 sinks same-value `mov [es:x],imm`
  stores and reorders constant init stores regardless of source order
  (`_ChangeHUDFilter` Pal0/1/2, `_LoadScottMission` zero-stores).
  `volatile` forbids the sink but changes the encoding to
  `mov byte [es:x],imm` — a different pinned form.
- **ASM encoding** — gold uses 386 `jcc near` (`0F 8x`) and imm16 forms;
  UASM emits short-jcc/imm8. Same instruction, different bytes
  (`_FlagRotate3D`, `_NDDot`, `_NDLine`, `_NPFFill`, `_ZClip`).
  MASM-era encodings; acceptable per the visual-equivalence criterion.

Genuine source fixes are the minority — maybe 15-20% of raw DIFFs.

## Source-shape techniques that worked

MSC6 code generation responds to *source shape*, not just semantics.
Small rewrites move the emitted code:

- **Expression form changes block order.** `_NHorz` cloud amount:
  `(a>b)?(100-(b/(a/100))):0` → `(b>=a)?0:(100-(b/(a/100)))` reproduced
  gold's `[0-arm][jmp][compute]` layout and shared store. 63→14 diffs.
- **Local buffer size = frame size.** `_RioMap` `char S[255]`→`S[376]`
  reproduced `enter 0x292` exactly — gold's `S` was contiguous with the
  `start_data` local above it. When `enter` sizes differ, recount the
  locals; an off-by-N usually means a different array bound or one extra
  scalar.
- **Globals vs locals.** Gold `_LoadScottMission` used global `MisFile`
  for fopen#1 (`mov [0xcba4],ax`) but a local `FILE *File` for fopen#2
  (`mov [bp-0xa],ax` + `push [bp-0xa]` at every fread). Push-site
  operands reveal which storage class the original used — check whether
  gold pushes `[imm]` (global) or `[bp-x]` (local) before guessing.
- **Register hints.** `register int n` put `NUM` in `si` for
  `_DrawXploSprite` (matching gold's `push si; mov si,[bp+0xc];
  imul bx,si,0xa`). Doesn't always work — `register int di2` in
  `_TakingOff` is ignored under `/Osegcl` (spilled to `[bp-4]`; `/Oe`
  diverges further).
- **Struct field widths.** Gold `_DoAltHover`'s `cmp [bx-0x4ece],-2`
  + `[bx-0x4ecc],-1` is a *dword* compare = `x == -2` on a `long` field —
  not an `x==-2 && y==-1` pair. Two adjacent word compares on a long
  boundary are the sign-extension check.
- **Behavior-pointer stores identify the target.** `DoAltHover` stored
  `2ad2:1236` = `Formation` (verified by body-identical match), not
  `FlyWayPoint`. Resolve gold's stored far pointer against gold's own
  function bodies, not our map.
- **Duplicate strings need duplicate labels.** Gold dedups nothing:
  `USAN01.WLD` appears twice (`_LoadFiles` case 2 vs default), and
  `"rb"/"mission.f14"/"No Mission Data"` appears twice in
  `LoadScottMission`. Label the second copy inside the GDSEG blob
  (`gstr274a`, `gstr302b/2b/303b`) and point the second use at it —
  restores both the extra distinct push and the tail-merged
  `push;push;jmp short back` error-path shape.
- **Per-occurrence string objects.** `_GiveSortInfo` pushes 18 distinct
  string addresses for 18 TXA sites — the original source used a fresh
  named constant per call site (equivalent to MSC6's no-dedup literal
  pooling), so reusing one gstr label per *content* loses half the
  function's data. Diagnose by listing every `push word 0xNNNN` in the
  gold extent in order, resolving each against the gold string table,
  and comparing to the source's TXA order. The fix is purely data:
  split the containing DB blob at each string start, add a label
  (`gstrNNN` where free, `gstrNNNb/c/d` suffixes otherwise), rewire the
  call sites, and delete the now-shadowed ORG stubs. Verify the other
  users of a repurposed gstr are dead (`#if 0`) before reassigning it —
  live sites like `SetUpCAP2`'s `TXA(gstr520)` pin the label's address.

## Segment/layout notes

- Gold's 79 `CODE_N` entries = our 78 real segments + **one phantom**:
  `0x204f` is a map split *inside* MESSAGE_TEXT (a function at `0x204f7`
  spans the `0x204f/0x2050` boundary — real segments can't do that).
  `0x1520` = our `CTRLVECT_TEXT` (int 1b/23 setvect block). No missing
  module.
- Object order in the link drives segment placement; don't reorder OBJS.
- Gold seg `0x3e2f` = MPSLIBM stubs; `_AvailSysMem` at `+0xe`.
- DSEG layout differences are pervasive and mostly *not* C-fixable —
  they come from declaration order across TUs and ORG-anchored blobs in
  `GDSEG.ASM`. gstrNNN labels are often `ORG`-anchored aliases
  (`_gstr303` = `ORG`'d label sharing an address with `_gstr329`).

## Compiler facts (MSC 6.00)

- `/O` letter `e` controls commutative-operand ordering AND register
  allocation together — can't get one without the other (`_GetWhoCover`,
  `_TakingOff`). Gold shows regalloc AND param-first compare order,
  suggesting retail's `e` pass ordered leaves differently than our
  6.00-alpha. Pinned as compiler-revision artifact.
- Constant-store reordering and same-value store sinking happen in the
  backend, not the opt passes — no `/O` combination disables them
  (`/Os` alone still groups).
- `enter` frame size is not decl-ordered; reordering declarations does
  nothing. Frame diffs mean different *counts/sizes* of locals.
- `register` hints only honored under `/Oe`.
- Tail-merge (`cross-jumping`) shares a `call` when the tail matches —
  even if pushed args differ (`push diffstr; jmp short -> shared call`).

## Practical gotchas

- `build_all.sh` arg is a *mode* (`c`/`asm`/`link`/`all`), never a
  module name — `build_all.sh riomap` silently does nothing.
- Source basenames are uppercase (`NHORZ.C`); `relink_check.sh` handles
  case, direct CL does not.
- `tools/relink_check.sh` is not executable — run `bash tools/...`.
- After recompiling, verify the OBJ actually changed before comparing
  (a PUBDEF disasm of the .OBJ catches "link used stale obj").
- `ndisasm` needs a file, not stdin; image = EXE minus header.
- In lifted `MPSREAL.ASM`, prefer `lea reg,[sym]` over `mov reg,offset`
  when gold used the 4-byte `lea` encoding — `mov reg,imm` is one byte
  shorter and silently shifts every following label. Raw `db` call
  sites (`db 0E8h,lo,hi`) do NOT adapt: gold `g6361` called the int21
  wrapper's `push bp` entry at `g646c`; a 3-byte `mov` shrank the
  intervening code so the same displacement landed on `push si`,
  unbalancing the stack (`pop bp` ate the return address → wild `ret`
  → data execution). Two such sites were fixed (`g6435`, `g6bcc`).
  Rule: preserve operand-size encoding on every instruction that sits
  between a raw-byte call/jump and its target.
- Gold pushes that look like code addresses (`0x32a5`) are DSEG offsets —
  find the base by matching a known string (`mission.f14`), don't assume.
- The `mrec`-style anonymous struct decls in `LOADMISS.C` are
  reconstructed from gold's field accesses — sizes were guessed from
  `fread` extents and may need revisiting if the frame is ever off.
